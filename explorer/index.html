Dive Manual RAG Explorer

A working walkthrough of a retrieval-augmented generation pipeline for approved, public diving sources. Every stage below runs live in your browser. Change the chunking in stage 3 and watch retrieval, answers and evaluation scores move in stages 4 to 7.

⚑The sample corpus is illustrative text written for this demo. It explains general diving physics and physiology in plain language and is not quoted from the Navy or NOAA manuals. It is not diving guidance.

Sources: decide what is allowed in

The license check happens before any parsing. Each source gets a manifest entry with its revision and license, and ingestion refuses anything not on the allow list.

Analogy: it's like only filling your tank at a verified fill station. Contaminated gas can't be fixed by a better regulator, and unlicensed or outdated text can't be fixed by a better prompt.

Parse: turn pages into clean, structured text

PDFs repeat headers and footers on every page, hyphenate words across lines, and flatten tables into number soup. Switch each cleaning step on and off to see what it fixes.

Analogy: parsing is rinsing your gear after a dive. Headers, footers and broken hyphens are the salt crust. Leave them on and they corrode every stage downstream.

Detect boilerplate by frequency, tables by structure

    
A line that appears on more than half the pages is boilerplate. Pull tables out with a table extractor and store them as rows, not prose.


from collections import Counter
import fitz, pdfplumber   # pymupdf, pdfplumber

pages = [p.get_text() for p in fitz.open(path)]
freq  = Counter(l.strip() for p in pages for l in set(p.splitlines()))
boiler = {l for l, c in freq.items() if l and c > 0.5 * len(pages)}

clean = ["\n".join(l for l in p.splitlines() if l.strip() not in boiler)
         for p in pages]
clean = [re.sub(r"(\w)-\n(\w)", r"\1\2", p) for p in clean]   # de-hyphenate

with pdfplumber.open(path) as pdf:
    tables = [t for pg in pdf.pages for t in pg.extract_tables()]

Chunk: choose the unit of retrieval

    
The sample corpus has 14 numbered sections. Fixed-size chunking ignores those boundaries. Section-aware chunking splits on section numbers, prepends a heading to each chunk, and only cuts inside a section when it runs past the size limit.

  

  
Analogy: chunks are dive slates. Too small and a procedure won't fit. Too big and you can't find the line you need at depth. Section-aware chunking writes one procedure per slate, with its title at the top.

  

    

      

        

          
          
        

      

      

      

    

    

    

  

  

    
Split on section numbers and carry a breadcrumb

    
Manuals number their sections, so use the numbering. Prepending the heading gives a mid-section chunk the context it lost when it was cut.


SEC = re.compile(r"^(\d+-\d+(?:\.\d+)*)\s+(.+)$", re.M)

def section_chunks(text, src, max_words=300, overlap=40):
    marks = list(SEC.finditer(text)) + [None]
    for m, nxt in zip(marks, marks[1:]):
        body  = text[m.end(): nxt.start() if nxt else None].split()
        crumb = f"{src['id']} {src['revision']} §{m[1]} {m[2]}"
        step  = max_words - overlap
        for i in range(0, max(len(body), 1), step):
            yield {"text": crumb + "\n" + " ".join(body[i:i+max_words]),
                   "section": m[1], **src}

Retrieve: lexical, semantic, and hybrid

    
BM25 matches the exact words in the query. The semantic column uses a stand-in scorer (TF-IDF with a diver-slang synonym map) to imitate what an embedding model does: "bends" finds decompression sickness without sharing a word with it. Hybrid merges both rankings with reciprocal rank fusion (RRF).

  

  
Analogy: BM25 is a buddy who only responds to textbook hand signals. The semantic retriever gets what you mean even when your signal is sloppy, but sometimes reads too much into it. Hybrid means diving with both buddies.

Hybrid retrieval in a dozen lines

    
RRF only uses ranks, so you never have to put BM25 and cosine scores on the same scale. k=60 is the usual default.


from rank_bm25 import BM25Okapi
from collections import defaultdict

bm25 = BM25Okapi([tokenize(c["text"]) for c in chunks])

def hybrid(query, k=60, w_sem=0.5, n=20):
    lex = bm25.get_scores(tokenize(query)).argsort()[::-1][:n]
    sem = vector_db.search(embed(query), limit=n)        # ids
    fused = defaultdict(float)
    for r, i in enumerate(lex): fused[i] += (1 - w_sem) / (k + r + 1)
    for r, i in enumerate(sem): fused[i] += w_sem       / (k + r + 1)
    return sorted(fused, key=fused.get, reverse=True)

Rerank: a closer look at the shortlist

    
A reranker reads the query and each candidate together and rescores them. A real system uses a cross-encoder. This demo uses a transparent stand-in that scores query coverage, heading match and focus (how much of the chunk belongs to one section), so mixed chunks from fixed-size chunking sink.

  

  
Analogy: retrieval is the wide sweep of a search pattern. Reranking is going back to each thing you found and checking it up close before you bring it to the surface.

Swap in a cross-encoder

    
Rerank 20 to 50 candidates and keep the top 4 to 6. Cross-encoders are slower than embeddings, which is why they only see the shortlist.


from sentence_transformers import CrossEncoder
rerank = CrossEncoder("BAAI/bge-reranker-base")

cands  = hybrid(query, n=30)
scores = rerank.predict([(query, chunks[i]["text"]) for i in cands])
top    = [cands[i] for i in scores.argsort()[::-1][:5]]

Answer: route first, then ground and cite

    
A router decides what kind of question this is before any generation. Table lookups are computed, never generated. Personal dive-planning or medical questions get citations and a referral, not advice. Low-confidence retrieval returns a refusal. Everything else gets an answer built only from retrieved chunks, with section citations.

  

  
Analogy: a good assistant works like a dive computer. It shows numbers it calculated, never numbers it guessed, and it tells you plainly when you are outside its limits.

  

    

    
In production an LLM writes the final wording from the chunks below. Here the answer is extractive (the best-matching sentences), so you can see exactly what grounding the model would receive.

Route, then constrain the prompt

    
Cheap rules or a small classifier can do the routing. The prompt forces citations and gives the model a way to say no.


ADVICE = re.compile(r"\b(can i|should i|is it safe|my dive|fly after)\b", re.I)

def answer(q):
    if ADVICE.search(q):        return refer_with_citations(q)
    if (m := DEPTH.search(q)):  return table_lookup(m)      # exact, no LLM
    ctx = rerank(q, hybrid(q))
    if max_score(ctx) < THRESH: return "Not covered by the approved sources."
    return llm(SYSTEM + fmt(ctx) + q)

SYSTEM = """Answer only from the context. Cite every claim as [§section, revision].
If the context does not answer the question, say so. Never compute
decompression schedules or give personal dive or medical advice."""

Evaluate: score every setting the same way

    
Sixteen test questions, three of them worded the way divers talk rather than the way manuals do, each labeled with the section that answers it. The scores update as you change chunking, the semantic weight, top-k or the reranker. Click a question to load it into the query bar.

  

  
Analogy: this is the checkout dive. Nobody gets certified on vibes. You run the same skills every time and score them the same way, so you know whether a change helped.

  

    

      

    

    
Recall@k: share of questions where a chunk from the right section appears in the top k. MRR: rewards finding it at rank 1. Top-1 purity: share of the first chunk's words that come from the right section, which drops when chunks mix sections. Context words: what you pay for in tokens.

    
Caveat: the semantic stand-in's synonym map was written by the same person as these questions, so its perfect score is optimistic. That is a leak from the test set into the system, the same mistake as tuning a prompt on your eval set. A real embedding model will score lower, and you should hold out questions written by someone else.

    

  

  

    
Start with retrieval metrics, then add answer metrics

    
Retrieval metrics need only labeled sections and run in milliseconds. Add LLM-judged faithfulness and answer correctness (for example with RAGAS) once retrieval is solid.


def recall_mrr(evalset, retrieve, k=4):
    hits, rr = 0, 0.0
    for ex in evalset:
        ranked = retrieve(ex["q"])[:k]
        rank = next((i for i, c in enumerate(ranked)
                     if c["section"] in ex["gold"]), None)
        hits += rank is not None
        rr   += 0 if rank is None else 1 / (rank + 1)
    return hits / len(evalset), rr / len(evalset)
